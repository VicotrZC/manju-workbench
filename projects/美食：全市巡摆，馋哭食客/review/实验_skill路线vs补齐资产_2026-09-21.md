## 三、结论：**B 明显更好，但代价是 3 倍出图**

- **B 赢在四件事**：景别（唯一一个做对了全景的）、坐骑、服装、场景 —— 全部来自**参考图**。
- **A 的失败点很集中**：**景别成了近景**。这不是偶然，是 skill 那条规则的副作用：

  > skill 法则 23①「**首镜单主体锚定**」要求锚定句写成「**画面主体：闫清…**」。

  这条规则的**目的是治「一张脸变两张脸」**（它自己的病灶记录写得很清楚），
  但它的副作用是**把模型推向人物肖像**——实测就是一张近景大头。
  **它治好了重复人物，换来了景别失守。**

- **两条都没把脸完全传过去**，根因相同：**画风锁与角色卡在互相拉扯**。
  画风锁要求「卡通渲染／清晰描边／**精致细腻的二次元五官**」，
  而 CHR-01 卡是**半写实**的成熟青年 —— 锁赢了，脸就被二次元化了。
  → 这一条**不是接线问题**，是**画风锁与角色资产的内在冲突**，需要用户拍板。

## 七、「为什么参考了人物图，人还是差距很大」—— 查文档后的完整答案（2026-09-21）

用户提问后，按 `agent.md` §一「先查官方用法」执行：**先读官方手册，再查社区**。
查完发现**两个**原因，并做了两组对照把它们分开。

### 原因 A：参考图的坐标网格与生成网格错位（文档记载的机制）

**权威出处**：`artokun/comfyui-mcp` 的 `qwen-image-edit` skill
「Resolution on an edit graph」一节（本仓库 `规矩.md` §10 早已引用它）。
原文机制：

> `TextEncodeQwenImageEdit` 与 `TextEncodeQwenImageEditPlus` **不接受尺寸参数**。
> 它们把**每一张**参考图缩到硬编码的 `int(1024 * 1024)` px —— **约 1.05 MP，
> 按【它自己的】宽高比** —— VAE 编码后作为 reference latent 交给模型。
> 模型把**参考 token 与正在生成的 token 放在同一个居中坐标网格**上，
> 所以参考位置 (i, j) 与输出位置 (i, j) 只有在**两个网格一样大**时才指同一个地方。
> ……网格差得远时，**模型无法跨网格复制细节，于是重新合成主体** ——
> 材质变塑料/CGI、印刷细节变成泛化形状。**什么都不报错，只是那张图不是你要的编辑。**

**我们自己的数字**（生成侧 latent = `VAEEncode(1376×768)` = **171×95**）：

| 参考图 | 尺寸 | 参考网格 | 与生成网格的差 |
|---|---|---|---|
| image1 空街场景 | 1376×768 (16:9) | 171×95 | **0** ✅ |
| image3 小电驴 | 1376×768 (16:9) | 171×95 | **0** ✅ |
| **image2（旧）CHR-01 全身卡** | **768×1152 (2:3)** | **104×156** | **67×61 格** ❌ |
| image2（新）16:9 头肩特写 | 768×432 (16:9) | 170×96 | **1 格** ✅ |

→ **这解释了「衣服和小电驴传过去了、脸没传过去」**：小电驴在正确网格上 → 完美复制；
角色卡在错网格上 → 脸被**重新合成**成一张泛化的脸。服装是低频属性，重合成也还在。

**做法**：把 CHR-01 卡裁成 **16:9 头肩特写**（`mz_C01_face169.png`，768×432）。
官方 model card 讲的也正是「based on an **input portrait**」。
⚠️ HF 讨论 #30（3 参考图）里那位作者**所有参考图都用完全相同的尺寸**、输出同宽高比 —— 同一条道理。

### 原因 B（**主因**）：8 步 Lightning ＋ CFG 1.0 关掉了官方那条 true-CFG 通路

**官方 model card 的 Quick Start**：`num_inference_steps: 40`、`true_cfg_scale: 4.0`、`negative_prompt: " "`。
`artokun` 的采样表同样把 `Standard edit` 定为 **40 步 / CFG 4.0 / 无 LoRA**，
只有 `Lightning` 两行才是 4/8 步 / CFG 1.0。
**而 Lightning LoRA 强制 CFG=1.0** —— 蒸馏少步省时间，代价可能就是身份细节。

### 两组对照（**只改一个变量**，所以能干净归因）

| | edit3 | edit4 | edit5 |
|---|---|---|---|
| image2 | 全身卡 2:3（错网格） | **16:9 头肩（对齐）** | 16:9 头肩（对齐） |
| 采样 | 8 步 / CFG 1.0 / Lightning | 8 步 / CFG 1.0 / Lightning | **40 步 / CFG 4.0 / 无 LoRA** |
| 实测耗时 | 67.5 s | 67.2 s | **317.9 s（4.7×）** |
| 脸像不像参考 | ❌ 差 | ❌ **仍然差** | ✅ **明显像了** |

**结论（干净归因）**：
- **edit3 → edit4 只改了网格 → 身份没有可见改善** ⇒ 网格错位**是真实存在的机制，但不是本例的主因**
- **edit4 → edit5 只改了采样参数 → 身份大幅改善** ⇒ **主因是 8 步 Lightning / CFG 1.0**

> **代价要讲清**：身份保真度是**用时间买的** —— 67 s → 318 s，按 ¥1.58/h
> 即 **¥0.029 → ¥0.140／张（约 4.8 倍）**。这是要用户拍板的取舍。

### 还没解决 / 新暴露的

1. **`edit5` 的景别变成了中近景**（正脸怼镜头），不是 `shot_size` 要的「全景」。
   **张力**：头肩特写当参考 → 身份传得好，但构图被带近。
   → 需要那个**可量的**构图约束（"人物占画面高度约 1/5"），且要与身份保真一起调。
2. **脸上的疤被画重了**：参考里是「一道很浅的陈旧小疤」，出图成了**一道明显的深色折线**，
   而且**左右反了**（参考在画面左，出图在画面右）—— 签名标记的镜像陷阱仍在。
3. **耗时 ×4.7 会影响产能口径**（`05_成本与产能.md` 的 t2i ≈¥0.018/张 是按 8 步算的）。
