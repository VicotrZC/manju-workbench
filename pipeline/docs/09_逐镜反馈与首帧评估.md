# 09 · 逐镜反馈与首帧评估

本文件记录 EP02 菜市入口试跑（2026-09-24）的可复用做法。它补充 `07_管线.md`：S1–S5 仍可提前准备，但同一动作链的首帧和视频不能全部预制后一次性提交。下一镜的画面状态必须取决于上一镜**实际生成并选用**的画面，而不是模型对上一镜的文字描述。

## 一、生产顺序

1. 从小说确定节拍、地点与动作落点；分镜须写明看得见的过渡动作。例如“骑车到菜市”要分解为街道、入口、通道、靠摊停车，不能直接从路上切到柜台。
2. 批量锁定不随镜头改变的东西：人物、服装、车辆、场景空间、固定道具、画风和台词。为每个场景列出**必须持续出现的可见物件**，例如猪肉摊的挂肉、灯、门、柜台。场景图先确定；首帧不能承担修补错误空间的任务。
3. 只制作当前镜的首帧。地点或机位大幅改变时，用已批准的资产合成新首帧；同一动作和空间的连续镜，优先用上一镜已选视频的真实交接帧。两种情况都记录所有视觉来源与职责。
4. 当前镜单独调用视频模型。生成后核对首帧是否真的保留输入首帧，抽查中间帧和末帧的人物、车辆、场景物件、动作及屏幕方向。**首帧正确但视频第 0 帧丢物件，也算失败**；EP02 交谈镜头的挂肉就是实例。
5. 从实际视频中选交接帧；剪辑中上一镜必须精确结束于这个帧。再据此制作下一镜首帧。不要拿 n=80 当下一镜输入，却让上一镜播放到 n=123。
6. 所有镜头通过后再剪辑与制作最终声音。H3 原生音轨可供预览，不代替清晰、准确、按角色锁定的正式对白。

## 二、每镜最少记录

镜号、剧本节拍、地点/机位、镜前状态、镜后状态、固定物件清单、首帧来源与生成模型、首帧文件、H3 工作流与版本、实际视频、抽帧检查结论、交接帧号、剪辑终点（exclusive）、下一镜首帧来源、耗时及重跑原因。静态图、实际视频和文字提示词三者不能互相替代。

逐镜检查至少分三层：① 首帧与资产是否一致；② H3 实际第 0 帧与输入首帧是否一致；③ 上一镜选中末帧与下一镜实际第 0 帧是否连续。人脸、车辆和固定布景物件都要检查。跨机位允许合法的画面变化，但必须确认物件没有凭空消失。

## 三、首帧模型对照试验

Qwen-Image-2.1 仅作为当前**非商用评估候选**，不预先替换已验证的首帧来源。试验要用同一批项目资产、相同镜头描述和相同 1376×768 交付画布，与现有首帧路线比较：人物脸与服装、蓝灰电瓶车结构、猪肉摊固定挂肉/灯/门、构图机位、文字伪影、出图时间、重试次数，以及交给 H3 后实际第 0 帧的保留率。至少测“街道→菜市入口”和“摊前两人交谈”两类不同复杂度镜头，不能只挑一张漂亮图。

记录具体模型版本、权重来源、推理框架、参数、参考图顺序、提示词、种子和许可。Qwen-Image-2.1 官方权重的研究许可只适合本阶段评估；未来若改用 API，需独立核对该 API 对商业使用及输出的条款。生产工具应把首帧模型作为可替换供应端：输入相同的资产与镜头状态，输出相同的图片、来源记录和质量检查结果，不把剧本/镜头表绑死在某个模型名称上。

官方资料：<https://github.com/QwenLM/Qwen-Image-2.1>、<https://github.com/QwenLM/Qwen-Image-2.1/blob/main/LICENSE>。

## 四、当前边界

EP02 入口桥段已证明逐镜交接可跑通，但它是人工反馈式试跑，还没有完整接入 `pipeline.py` 的 S0–S10 自动状态机；不能将其登记为工业化全自动能力。原粗剪里的摊内交谈、声音和买肉装车细节仍需分别修复。该案例的镜头选择与检查见 `projects/美食：全市巡摆，馋哭食客/storyboard/SCN03_镜头表.json` 和 `production/EP02_SCN03_bridge_QA_2026-09-24.md`。
