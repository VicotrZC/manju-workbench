## 二、★ 结论：报告里那条"少抽卡 = 省钱杠杆"，对我们基本不成立

调研报告的核心结论之一是：

> **10:1 的抽卡率会把 6 元/分钟的基础算力放大成 60 元/分钟。**
> "省钱的逻辑是少抽卡。"

**这条成立的前提是"按 API 付费"。** 而我们是**自有租用 GPU + 本地推理**，所以：

| | 口径 | 数值 |
|---|---|---|
| 行业"纯算力" | API 计费 | **40–200 元/分钟** |
| **我们** | 租卡计时 | **2.8–28.4 元/分钟** |

**即使按最悲观的 10:1 抽卡，我们每集也只有 ¥47。**
→ **抽卡率对我们是一个"产能"问题（要等多久），不是一个"成本"问题（要花多少钱）。**

**这对工程优先级是实质性影响**：
调研建议我们把「分镜图=首帧、九宫格批量出图、ref 库完备性预检」当成**成本杠杆**去做；
**对我们要换个理由**——它们省的是**我的时间**，不是钱。
**理由变了，但结论没变：还是该做。**（因为下一节）

## 二·补、本地 vs 云 API 的单张成本（2026-09-20 新增，用户实测后定案）

### 我们的真实单价（按用户实际租价 **¥1.58/小时**，不是文中的 ¥2）

¥1.58 ÷ 3600 = **¥0.000439/秒**。

| 操作 | 实测耗时（`workflows/scene/README.md`） | 折算 |
|---|---|---|
| t2i 8 步（场景空景） | 40.3 s | **¥0.0177/张 ≈ 1.8 分** |
| edit 8 步（派生视图） | 52.3 s | ¥0.023/张 ≈ 2.3 分 |
| edit ＋ angles LoRA（换机位 4 步） | 39.5–43.4 s | ≈¥0.018/张 |
| **整张场景卡（11 张）** | ≈8 分钟 | **¥0.21/套** |

**理论吞吐上限 ≈ 89 张/小时**（3600 ÷ 40.3）。
⚠️ 未验证 40.3 s 是否含模型加载；且 **Qwen ↔ H3 来回切换每次要重新加载 1–3 分钟**，这是真实吞吐杀手。

### 对照：Seedream 4.0（火山方舟）

**¥0.2/张**。三个独立来源一致：`ai.bimant.com`（2026-09-20 更新，火山方舟与 PPIO 派欧云均为 0.2 元）、知乎价格对比文（「seedream-4.0 官方 0.20 → 渠道 0.2210 元/张」）、LLMRates 价格历史（image_price 0.2）。
⚠️ **火山官方计费页是 JS 渲染，正文未直接读到**；上述为三方交叉，标**未直接核实**。

| | 本地 Qwen-Image | Seedream 4.0 |
|---|---|---|
| 单张 | **¥0.0177** | ¥0.20 |
| 便宜倍数 | **11×** | — |
| 800–1500 张（100 集漫剧的量） | **¥14 – 27** | ¥160 – 300 |

**盈亏平衡点：¥1.58/h ÷ ¥0.2/张 = 7.9 张/小时。**
→ **只要开机期间平均每小时出 8 张以上，本地就比 Seedream 便宜。** 理论吞吐 89 张/h，门槛几乎踩不到。

### ★ 结论一：成本差额（¥150–270/百集）**不构成决策依据**

与 §三 一致：人力占六七成，**唯一值得优化的是返工次数**。一次返工的人力就超过这个差额。

### ★ 结论二：**抽卡对我们是免费的，工业界不是**

本地 1.8 分/张 → **抽 10 张才 1 毛 8**。工业界 ¥0.2/张 必须算着抽卡。
→ 我们**可以比工业界更狠地抽**。这是本地路线被低估的优势，也是 §二 那条"抽卡率对我们是产能问题不是成本问题"的量化版。

### ★ 结论三：**用户实测后拍板，不引云图像通道**（2026-09-20）

用户用已有的 ChatGPT Plus ＋ 即梦/Seedream 手工出图与本地对照，目视判断（**感知类结论由人判断，此为权威口径**）：

> 「没有太多明显的差距。主要差距可能就是**风格切换**，它们比较灵活，我们需要摸索，就这点差别。其他的大差不差。」

→ **不引云通道**。理由不是钱，是**质量差距不足以换来一次返工**。
→ 唯一被确认的真实差距是「风格切换灵活度」，详见 `docs/中文skill生态调研_2026-09-20.md` §4 的三条补法。

## 三、我们真正的成本是人力，而且和行业一致

调研里三层口径互相印证同一件事：

| 来源 | 口径 | 人力占比 |
|---|---|---|
| 魔方集团叶萍（一手） | AI 漫剧全成本 | **六七成** |
| 一份完整 12 集精品漫剧预算表 | 人力 40.6 万 / 总投 50 万 | **83%** |
| 另一口径 | 单次生成任务的 API 花费 | 视频占 92% |

**前两条是全成本口径（人力为大头），第三条是单次任务口径（算力为大头）——不矛盾，但不是一回事。**

**推算到我们**：28 集 × 100 秒 ≈ 46.7 分钟成片。
- 算力：**¥220–1,330**（按 3.5×–10× 抽卡、2 元/小时）
- **其余全是人力**（写戏层、改分镜、盯预演、审图、返工）

→ **本项目唯一值得优化的成本项是「返工次数」。**
→ 这正是"先写戏层、再写分镜、分镜只做输出不做新决定"这条管线的**经济理由**：
  **每一次戏层改动，如果已经编了镜号，就要重编一遍镜号——那是最贵的一种返工。**

## 四、⚠️ 商业模式风险：万播收益崩塌（必须让决策人知道）

调研给出一条解释力很强的因果链：

| 时间 | 万次播放收益 |
|---|---|
| 2025 上半年 | 约 **100 元** |
| 2025 下半年 | 30–100 元 |
| **2026 年** | **5–10 元**（**跌 90–95%**） |

**传导**：分账收益跌 90–95% → 平台/甲方压价 → 承制价从 5000 元/分钟跌到几百元/分钟。

**这条比"完播率 12.3%"更能解释"AI 短剧占榜七成、回本率 1.3%"。**

**对我们是直接的**：

| 变现路径 | 2026 年价位 | 28 集（46.7 分钟）对应 |
|---|---|---|
| 平台分账（按播放） | **跌到 2025 上半年的 1/10 ~ 1/20** | — |
| 平台保底采购 | 3,000 / 5,000 / 8,000 元/集 | **8.4 万 – 22.4 万** |
| 定制短剧 | 1 万 – 2 万元/分钟 | **46.7 万 – 93.4 万** |
| AI 短剧承制（普通） | 几百 – 1,500 元/分钟 | 1.4 万 – 7 万 |

**→ 如果目标是"平台分账"，2026 年的单位收益只有 2025 年上半年的 1/10 到 1/20。**
**→ 这个决定不该由我做，但必须以数字形式摆在台面上。**

（另：投资分级里 **<30 万可避开发行牌照**，而我们的算力成本只有四位数——
**只要人力不计价，本项目的现金投入极小。这是它相对"雇佣团队"的结构性优势。**）

## 五、两条要纳入 SOP 的实战项

调研抓取 5 套 B 站教程的完整分 P 目录后发现：**只有一套**把下面两项**单列为课时**——

| 项 | 说明 | 我们的现状 |
|---|---|---|
| **过人脸审核的方法** | 合规过审在实战中已是必修 | **未做**，也**没有方法论** |
| **废片变成片技巧** | 废片复用是实战必修 | **未做**。我们目前 71.3% 的废片是直接丢的 |

**→ 这两项说明**：合规过审与废片复用**已经是行业实战必备**，但**公开方法论普遍缺失**。
**→ 我们的态度**：不假装已经解决。列入欠账，等 C 段生成跑起来后**用自己的废片做实验**。
