## 下载/装模型时踩过的坑（**别再踩**）

| 坑 | 症状 | 正解 |
|---|---|---|
| **`aria2` 测速会骗人** | `ls -la` 立刻显示 3.8GB，算出「95 MB/s」 | 那是 `fallocate` **预分配的空洞**。要看 `aria2` 自报的 `DL:`，或 `du` 的块占用；**别用 `stat`/`ls` 判断进度** |
| **`du -sb` 在满大小文件上也不等于文件大小** | 下完的文件显示 88% | 稀疏块占用可能小于文件大小。**没有 `.aria2` 控制文件时，要看 `stat`** |
| **`pkill -f 'aria2c.*<文件名>'` 杀不干净** | 换了下个文件就匹配不到；多个 aria2 抢同一文件 | 先杀**脚本**再杀 `aria2c`（否则脚本立刻把它拉回来），并**轮询确认进程数为 0** |
| **两个进程用不同 URL 写同一个文件名** | 我一度同时从 `flux2-dev`（非商用）和 `flux2-klein-4B`（商用）写 `flux2-vae.safetensors` | 文件必然损坏。**一次只跑一个实例**，启动后验证 `pgrep -c -x aria2c` == 1 |
| **`grep` 把日志当二进制跳过** | 关键词检查全空，看起来像"脚本没跑" | `aria2` 的 `\r` 进度条让日志变二进制 → 用 `grep -a` |
| **PowerShell 吃引号** | `ssh/rc.py 'cmd "x"'` 报 bash 语法错 | 把远端脚本写成**文件**用 `ssh/put.py` 传上去再 `bash` 跑 |
| **hf-mirror 会限流** | 16 路并发之后单文件掉到 134 KiB/s | 同一文件改从 **ModelScope** 取（实测 3072 KiB/s，**快 23 倍**），但**必须先比 sha256** |

> ⚠️ **一条重要的排除性结论**：那次「各源都只有 ~0.5-1 MB/s」的测速**是在 aria2 还在抢带宽时做的，全部作废**。
> 干净的对照显示这台实例的管子约 **2-3 MB/s**，不是 0.5。**测带宽前必须先确认没有别的下载在跑。**
