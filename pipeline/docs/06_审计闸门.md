## 一、为什么会有这个文件

2026-09-21 买肉场成片被用户判定整体跑偏。**八条缺陷里没有一条是"生成失败"**：

| 缺陷 | 性质 |
|---|---|
| 成片是写实质感，锁定的画风是候选 I | 上游文本没落到提示词 |
| 一场对话戏做成默片 | 上游文本没落到提示词 |
| 戏的 B1 整拍（骑车赶到菜市）一帧没有 | **分镜层把节拍吞了，没有任何程序在看** |
| 摊主长了胡子、闫清的疤没写、GEO 块没逐字进 | 上游文本没落到提示词 |
| 屏上乱码中文却报了"无乱码" | **验收标准是我自己编的** |

**全部是"上游文本没有落到下游产物里，而当时没有任何程序在看这件事"。**
当时的验收标准是「机位没漂／构图对得上／没烧字幕」—— 那是**技术验收**，不是**戏的验收**。

所以本闸门只回答一个问题：**上游写的每一样东西，到底有没有落到这一条工作流里。**

---

## 二、三道闸门

| 闸门 | 时机 | 谁跑 | 拦什么 |
|---|---|---|---|
| **chain** | 随时 | 纯脚本 | 层链断裂、**节拍被吞**、镜头表缺列、首帧未归档、首帧画风血缘 |
| **preflight** | **每一次生成之前**（生图、生视频都算） | 脚本出审计包 → **子 agent 判** → 脚本封存 | 提示词层面的全部不变量 |
| **postflight** | **一个项目/一场做完之后** | 脚本出审计包 → **子 agent 审流程** | 流程本身的漏洞，产出"要新增哪条检查" |

```
python tools/pipeline_audit.py chain      <项目>
python tools/pipeline_audit.py preflight  <项目> <工作流名>     # 出审计包 + 机械检查
python tools/pipeline_audit.py packet     <项目> <工作流名>     # 把审计包打印出来给 agent
python tools/pipeline_audit.py seal       <项目> <主题> <判定.json>
python tools/pipeline_audit.py verify     <项目> <工作流名>     # run.py 提交前调它
python tools/pipeline_audit.py postflight <项目>
python tools/pipeline_audit.py status     <项目>
python tools/pipeline_audit.py sync-prompts <项目>   # 把提示词抽到 prompts/（纯派生，不做内容决定）
```

**`tools/run.py` 已经把它接成硬闸门**：提交前先跑 `check_before_gpu.py`，再跑 `verify`。
**没有有效封条 → 拒绝提交**（`--skip-gate` 可跳过，属明确的自担风险）。

## 三、封条机制（为什么"忘了审"这件事被消除了）

脚本没法自己拉起子 agent，所以用**哈希绑定**来保证"审的一定是当前这一版"：

```
preflight  →  .work/audit/packets/<项目>.<工作流>.packet.json     （审计包）
子 agent   →  projects/<项目>/review/audits/<工作流>.verdict.json  （判定，人/agent 写的）
seal       →  projects/<项目>/review/audits/<工作流>.audit.json    （封条，程序写）
                 └─ 里面钉着被审文件（提示词 / 戏 / 镜头表 / GEO / audit_rules）的 sha256
verify     →  重算哈希；**任何一个变了 → AUDIT-02 过期 → 拒绝提交**
```

**改了提示词就必须重新审。** 这不是靠自觉，是靠哈希。

另一条硬约束：**机械 ERROR 不许被判 pass 盖过去。** `seal` 会数审计包里的 ERROR，
判定若写 `pass` 却留着未处理的 ERROR，直接拒绝封存 —— 要么修，要么在 `waivers` 里
**逐条给理由**（`{"code": "...", "reason": "..."}`）。这是防止 agent 当橡皮图章。

## 四、检查码表

### 层链（`chain`）

| 码 | 判据 |
|---|---|
| `CHAIN-01` | 剧本层文件缺失 |
| `CHAIN-02` | 分镜引用的资产图不在位（`01_资产规范` §〇：无图不进分镜） |
| `BEAT-01` | **戏里的节拍没有任何镜头认领** —— 这一拍会整段消失在成片里 |
| `BEAT-02` | 镜头认领了戏里不存在的节拍（分镜新增了剧情决定） |
| `SHOT-01` | 镜头表缺字段（`beats/shot_size/lens_mm/dist_m/visible_w_m/frames/first_frame/framing_en/workflow`） |
| `SHOT-02` | **首帧文件不在仓库里** —— 不归档则这一镜不可复现、不可审计 |
| `SHOT-04` | **镜头的工作流文件不存在**（典型成因：一个工作流被反复改写成四镜，把中间那镜覆盖丢了） |
| `SHOT-05` | **首帧画风血缘**：出首帧的那条工作流没过画风闸门 |

> `BEAT-01` 是「骑车赶到菜市整拍丢失」那类事故的**唯一防线**。
> 戏文件是节拍的唯一权威，程序直接解析 `**B1 ｜ …**` 与五通道表格。

## 五、画风那一条为什么这么写（实测标定，别再记错）

| 样本 | 提示词总长 | 画风句位置 | 画风句占比 | 结果 |
|---|---|---|---|---|
| `STYLE_I_H_mature` 探针 | 366 字 | 末段 | **33%** | 画风生效 ✅ |
| `FF_EP02SC01_shot`（四镜首帧真正用的） | 805 字 | **第 663 字** | **12.6%** | 画风失效 ❌ |
| `FF_EP02SC01_C_guochuang_t2i` | 也带画风句，也是 t2i | 末段 | 低 | **一样失效** ❌ |

⚠️ **当时记的教训「画风只能走 t2i，不能靠 edit 合成」是错的** —— C 路线就是 t2i，一样失效。
真正的变量是**占比与位置**。教训记错，所以 2026-09-21 又踩了一遍。

**并且**：成片的画风由**首帧**决定，不由 H3 提示词决定 —— H3 的 `detailed_description` 里
画风句好好地在最前面，首帧是写实的，成片就是写实的。
所以画风闸门必须掐在**出首帧的那条工作流**上（`SHOT-05`）。

> ⚠️ `style_ratio_min` 的下限（t2i 0.20 / h3 0.06）是**按上面三个样本标定的，只有三个样本**。
> 它是提示器，不是定律。要改阈值请连同标定样本一起改，并写进 `audit_rules.json`。

## 六、新项目怎么接入（三步）

1. 建 `projects/<项目>/audit_rules.json` —— 登记**这个项目自己的锁定件**：
   画风锁定句（原文照抄）、签名标记、正向否定锁、画布、GEO 文件、剧本文件、镜头表路径。
2. 建 `projects/<项目>/storyboard/<场次>_镜头表.json` —— **机器可读的镜头表**。
   没有它，节拍覆盖无从核对（这正是 B1 被吞掉的原因）。
   字段：`id / beats / shot_size / framing_en / camera / lens_mm / dist_m / visible_w_m /
   frames / first_frame / first_frame_workflow / workflow`。
3. 每次生成前：`preflight` → 子 agent → `seal`。项目做完：`postflight` → 子 agent → `seal`。

**子 agent 派活时把文件路径直接写进 prompt**（`规矩.md` §7：子 agent 与 `skill` 工具都调不到仓库内 skill）。

## 七、边界（`规矩.md` §12 的正面落实）

**本程序报"通过" ≠ 内容合格。**

| 它管 | 它不管 |
|---|---|
| 上游写的有没有落到提示词里 | 好不好看、像不像、表演能不能接受 |
| 文本自洽、数值合法、哈希一致 | **首帧是不是真的按 85mm/1.4m 取的景** |
| 节拍有没有被吞 | 节拍拍得对不对 |

第二条尤其要记住：**"S03 没守住大特写"这一类，机械检查抓不到** ——
提示词里写着 `close shot`，画面可以是任意宽窄。这类只能靠子 agent 看图或用户看片。

**会误报的检查器比没有检查器更糟**（`规矩.md` §5.C 第 14 条）。
本程序的每一条检查都在**已出问题的真实样本**上跑过，确认它报的都是真问题。
新增检查请照做。
