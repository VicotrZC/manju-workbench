## 〇 · ⚠️ 两条首帧路线并存，**节点图不同、不能直接互换**（2026-09-21）

同一天里从两台机器各自走通了两条出首帧的路线，它们**不是同一个模板**：

| 路线 | 工作流 | 节点图 | 判据 |
|---|---|---|---|
| **A · 纯 t2i**（本文档的 S6 模板法） | `FF_EP02SC02_S00.json` | **11 节点、0 个 `LoadImage`** —— 只有文本编码器 ＋ `EmptySD3LatentImage` | 画风靠**提示词**（画风句在第 0 字、占比 ≥20%，`WF-02/03/04`）；身份靠**提示词里的签名标记英文原文**（`WF-07`） |
| **B · 参考图路线** | `FF_EP02SC02_S00_edit2.json` ／ `_skill.json` | 含**图输入节点**（把资产图喂进去） | 新增 **`CHAIN-03`：首帧必须用参考图**；画风与身份靠**参考图**传过去 |

**实测对比（另一台机器做的实验，提交 `f7dfb35`）**：B 明显更好，**代价是 3 倍出图**。
其中一次结论是「**衣服传过去了、脸没传过去**」（`e94a82f`）。

⚠️ **两条不可混淆的推论**：

1. **`CHAIN-03` 只对 B 路线的首帧工作流成立。** A 路线的 t2i **没有图输入节点**，
   拿它去要求 A，就是在要求一件它**结构上做不到**的事（会变成"永远过不去"的判据错位）。
2. **两条路线的审计判据不同。** A 的命门是 `WF-02/03/04`（画风句占比）；
   B 已经由参考图承担画风与身份，那几条的**鉴别力要重新标定**。
   混用会出现"拿 B 的尺量 A"或反之，**两边都误报**。

> **待用户拍板**：出首帧走哪条路线。拍板之前**两套工作流都留在盘上、都别删** ——
> 它们各自对应不同的判据集。

看当前状态：`python tools/pipeline.py status <项目>`
可视化：`python tools/pipeline.py ui <项目>`

### 每个阶段配套的命令

```bash
pipeline.py brief    <项目> <阶段>     # agent 作业单：该读什么方法、要交什么、怎么验
pipeline.py scaffold <项目> [--write]  # S4 脚手架：机械能抽的先抽出来，抽不出的留 TODO
pipeline.py gen      <项目> <阶段>     # **自动生成**：组请求 → 调模型 → 落盘 → 跑门禁 → 不过打回重做
pipeline.py qc       <项目> [--write]  # S9 机械合规：自解 MP4 容器，填机械项、留语义项
pipeline.py run      <项目> [--shot S01] [--dry]   # S8 提交生成（**先自己过 S7**）
pipeline.py probe    <项目> <mp4>      # 单文件容器解析
pipeline.py gate     <项目> <阶段>     # 只跑某一个阶段的门禁
pipeline.py audit-all <项目> [--all-scenes]        # S7 备料：逐镜出审计包
pipeline.py seal-all  <项目> [--all-scenes]        # S7 收口：逐镜封存判定
```

`gen` 支持 **S2 / S4 / S6 / S7**。其中 **S6 走的是模板法**，见下节。

## 二·补一 · S6 是「模板法」：模型不画工作流

用户 2026-09-21 的架构要求：**「模型负责生成和审查，执行面交给电脑」**。

工作流是一张**几十个节点、二十几条连线的图**，让模型从零写必然出错
（节点 id 与 link id 对不上、连线指错端口 —— 而且**这类错在跑之前看不出来**）。
所以 S6 的分工是：

| 谁 | 干什么 |
|---|---|
| **程序** | 画节点图与连线（照已验证过的模板）；拼装**全部锁定件** —— 画风句、GEO 英文块、角色签名标记与正向否定锁、戏里的对白与 VO 原文、禁字幕句、帧数画布种子 |
| **模型** | 只写「镜次专属」的剧作文本：动作分段时间轴、音景、配乐、每个 Subject 在拍内怎么演化 |

**锁定件从此不可能被模型改写或漏掉**（规矩 §5.C.12 的正解：
别指望模型记住，**把它该记的东西从它手里拿走**）。

产物一镜两条：`workflows/FF_<场次>_<镜号>.json`（t2i 首帧）＋
`workflows/<场次>_<镜号>_h3.json`（H3 六段式）。

### ⚠️ 两条在 t2i 上**互斥**的判据（必须知道，否则会反复误报）

| 判据 | 要求 | 冲突点 |
|---|---|---|
| `WF-04` 画风句占比 | t2i **≥ 20%** | 画风句是**固定 100 字**的串，所以描述段上限约 400 字 |
| `WF-10` 取景句位置 | `[Shot 1]` 后 400 字内 | 取景句可以写得很细（构图信息都在里面） |

→ 所以 **t2i 用取景句的压缩版**（`pipeline.py` 的 `framing_t2i`：只删冗余限定词与固定短语、
**分句一个不删**），**h3 用 `framing_en` 原文**。
**审计员必须被告知这条**，否则会把合法的压缩判成「取景句没原样进入」
（`tools/s7_verdict.py` 的提问稿里写明了）。

### ⚠️ 装不下时**按档整档丢**，不是"算个预算超了就跳"

| 档 | 内容 |
|---|---|
| 1（**永不丢**） | 画风句 ／ 取景句 ／ **人物句（含身份锚英文原文）** |
| 4 | 无文字声明 |
| 5 | 道具 |
| 6 | 场景 |

**丢到没有身份锚就报错，不许静默生成。** 2026-09-21 实测教训：
前两版用「算个剩余预算、超了就跳过」，结果取景句过长时人物句被**静默挤掉**，
生成了一张**没有身份锚**的提示词 —— 而自检又在空列表上遍历，什么都没查到，一路放行。
**静默丢必需项比报错危险得多。**

## 二·补二 · 多场次（一个项目可以有多场戏）

2026-09-21 拆出 SCN-02 之后新增。**行规：一个地点一场戏** ——
B1「骑车到菜市」是室外、B2–B5 是摊内，两者不可能共用一个坐标系
（GEO 是「一个场次一份、一个坐标系」）。

| 机制 | 说明 |
|---|---|
| 场次发现 | 一份 `storyboard/*_镜头表.json` ＝ 一个场次 |
| `beat_scope` | `{场次: {script, beats}}` —— **每场读自己那份戏、只管自己那几拍** |
| `default_scene` | 不带 `--scene` 时用哪一场 |
| `--all-scenes` | 批量命令（`audit-all`／`seal-all`）跑**全部场次** |

⚠️ **`script` / `shot_table` / `geo_file` 三个单值键只够单场次项目用。**
多场次下必须靠 `beat_scope` 与按场次解析（`all_shot_tables` / `table_for_workflow` /
`geo_rel_for`）。**"只跑默认那一场"会静默漏掉另一个场次 —— 那是最危险的失败方式。**

判据：`BEAT-01`（本场有拍没人认领）／`BEAT-02`（全项目都没这个拍号）／
`BEAT-03`（登记与戏对不上）／`BEAT-04`（认领了别场的拍，**并报出属于哪一场**）。

## 二·补 · S8 与 S9 原来只有门禁、没有工具

2026-09-21 补的两环 —— **光有门禁不算管线，得有人真的去干那件事**：

| 阶段 | 原来 | 现在 |
|---|---|---|
| **S8 连服务器生成** | 只会检查"产物在不在"，**从不提交** | `pipeline.py run` 按镜头顺序提交；**自己先过一遍 S7**，不过就拒绝；中途失败就停（云机一次只跑一个占任务，规矩 §5.A.4） |
| **S9 按设定检查内容** | 只会要一份 JSON，**从不产出它** | `pipeline.py qc` **自己解 MP4 容器**（本机没有 ffprobe）算出画布／帧数／时长／帧率／音轨，填进记录；**语义项留空等人** |

`qc` 实测输出（买肉场四镜）：

```
S9 合规检查 · SCN-01 —— 机械项 20 通过 / 2 不过
❌ S01  采用版本  期望 一镜一版　实测 EP02SC01_S01_00002_.mp4／EP02SC01_S01_00001_.mp4
✅ S01  画布 1376×768 ／ 帧数 175 ／ 时长 7.292s ／ 帧率 23.999 ／ 音轨 mp4a 32000Hz 2ch
✅ S02  画布 1376×768 ／ 帧数 158 ／ 时长 6.584s ；✅ S03 192 帧 8.0s ；✅ S04 175 帧 7.292s
语义项 5 条**未检查**：画面可见文字／景别与机位／服装与造型／站位与轴线／音轨内容
```

**「同一镜有多个产物」算不过**：S01 和 S03 各有两个版本，
**哪一版是采用的必须由人写下来 —— 程序不替人选。**

## 三、三条硬设计（**这三条就是"程序兜底"**）

### 1. 状态不存，每次现算

`scan()` **现场重跑全部门禁**，不读缓存、不信上次的结论。
`pipeline_state.json` 里**只存 agent 的判定与说明，不存阶段状态**。

> 理由：如果界面显示的是上次算的，"程序兜底"就退化成"程序凭记忆汇报" ——
> 和大模型凭记忆汇报是同一种不可信。

### 2. 默认全跑，不做级联短路

上面没过，**下面照样算**，只在显示上标「轮不到：上面卡在 Sx」。

> 短路只能看到第一个错。买肉场那一轮我就是"改一个看一个"，
> 结果八个问题分八轮才发现。全跑一次摊开，才能一眼看全。

### 3. 产物必须晚于封条

`S8` 不只查"有没有产物"，还查**产物时间戳 vs 封条时间**：

```
❌ [S8-03] 镜头 S01 的产物（09-20 14:10）早于封条（09-20 17:54）—— 先生成后补审的
```

> 只查存在性会显示"通过"，读起来像"生成没问题"——**买肉场四镜正是这样**：
> 产物在审计闸门存在之前三小时就出来了。改完之后，这一条立刻报出来。

## 四、agent 步骤怎么被兜底

**程序不替 agent 创作，程序只保证三件事**：

1. **该它看的它看了** —— `brief` 命令给出该阶段必须读的方法文件清单（含外部 skill），
   并标出哪个文件不在。
2. **该它交的它交了** —— 产出必须符合 schema（`S4` 查 `characters/props/scenes` 三段、
   每项要有 `id`／`files`；`S2` 查镜头表 9 个字段）。
3. **交了之后没被偷改** —— 复用 `06_审计闸门.md` 的封条机制，哈希绑定。

**agent 报"通过" ≠ 内容合格**（`规矩.md` §5.C 第 12 条）。
管线只保证形式与追溯，**审美判断永远留给用户**（`规矩.md` §5.C 第 11 条）。

## 六、边界（`规矩.md` §12 的正面落实）

| 管线管 | 管线不管 |
|---|---|
| 阶段顺序、产出齐不齐、门禁过没过 | 好不好看、像不像、表演能不能接受 |
| 提示词与上游文本对不对得上 | 首帧是不是真的按 85mm/1.4m 取的景 |
| 产物是不是审过的那一版生成的 | 画面里有没有乱码文字、服装对不对 |
| agent 该交的判定交没交 | agent 的判定对不对 |

**S9 之后的"合规"只有一半能机械判**：尺寸／帧数／时长／音轨可判（本机无 ffprobe，
目前报成 WARN 待测）；**画面内容判不了，必须落成 `review/<场次>_合规检查.json`
并标注 `verified_by_human`**。没有这份文件，S9 直接 ERROR ——
因为买肉场就是「我把"画面无乱码文字"写进验收，而那是编的」。
